# Make IndexedDB the authoritative client store

Each Clerk user ID has a retained IndexedDB Account Cache containing immutable canonical generations, an atomic active-generation pointer, actor and Revocation Handle metadata, canonical accepted records, and a separate Pending Overlay. Allocating a Progress actor counter or Problem Note local revision, updating local materialized state, and replacing its pending delta occur in one transaction; React and `BroadcastChannel` are notified only after commit, and an aborted transaction silently restores the previous rendered value without consuming the identifier. Cross-tab messages carry only the account ID, affected keys, and local commit sequence, so every tab rereads the authoritative records.

Bootstrap writes to a temporary generation, validates it, overlays all pending mutations, and switches the active-generation pointer atomically before deleting the previous generation. An acknowledgement for an older mutation cannot replace a newer pending value. If an IndexedDB schema upgrade fails, Codejeet preserves the database untouched, renders empty Progress and Problem Notes for that session, accepts no apparently successful edits, and leaves recovery to a later compatible release.

The one-time legacy importer reads `leetcode-checked-items`, `leetcode-problem-notes`, `leetcode-problem-notes-meta`, and `leetcode-problem-notes-deleted`, but imports only true Progress values and nonempty valid notes. It hashes the source values, atomically writes accepted mutations and a completion digest, verifies the result, and then removes only those four keys. Repeating an interrupted import with the same digest is harmless. Imported Progress joins canonical Progress; an imported note becomes pending only when no canonical value or delete register exists for its slug, so Account Data wins every conflict.

The last authenticated account remains Locally Active through token expiry and temporary authentication loss, with synchronization stopped but offline edits allowed. Explicit sign-out switches every tab to the Public View without deleting IndexedDB. Activating another Clerk user switches directly to that user's cache and never exposes, copies, or uploads the previous account's records. The worker starts at the application shell; public content and empty controls render without a loading indicator while IndexedDB hydrates, and pre-hydration intent is queued only for the unchanged authenticated identity.
