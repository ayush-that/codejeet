# Deployment and verification

CodeJeet has two deployment surfaces: public educational content and authenticated learning data. Public pages and question data are generated by the Next.js/OpenNext build. Progress and Problem Notes are Account Data, stored in the browser's IndexedDB Account Cache and synchronized to server-readable D1 through the Cloudflare Worker and per-account Durable Object.

## Prerequisites

- Configure Clerk production authentication with Google as a Clerk social connection using production OAuth credentials. Use the prebuilt Clerk modal, not Google One Tap or custom OAuth.
- Enable verified-email linking and one active Clerk session. Verify the `user.deleted` webhook and its signing secret before enabling deletion flows.
- Configure the Worker, Durable Object, D1, asset, and R2 bindings in the deployment environment. Keep `SYNC_HMAC_SECRET`, Clerk secrets, webhook secrets, and all other credentials out of git and build logs.

## Safe rollout order

1. Review the exact Worker, Durable Object, D1, Clerk, and R2 configuration for the target environment.
2. Apply additive D1 migrations before activating a Worker that reads the new schema. Do not remove legacy tables or adapters in this rollout.
3. Build the Worker and run the asset-count/size guard. Preserve the OpenNext R2 cache and cache binding; investigate unexpected asset growth before upload.
4. Activate the Worker only after the migration and binding checks pass. Keep the legacy D1 mirrors and `/api/progress` and `/api/notes` compatibility endpoints for the rollback window. They preserve old response contracts while canonical Account Data remains authoritative.
5. If rollback is required, restore the previous Worker while retaining additive schema. If the new Worker has served traffic, keep compatibility mirrors populated until the rollback window closes.

## Verification matrix

Run evidence at each layer, using one consistent production hostname for browser checks:

| Layer      | Required evidence                                                                                                                                                                                                                                          |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node       | Codec fixtures, malformed/non-canonical input, CRDT laws, registry validation, cache and compatibility behavior, and failure-policy tests pass.                                                                                                            |
| Workers    | Durable Object FIFO, D1 batch atomicity and rollback, contiguous revisions, actor limits, shard split/reconstruction, migration, deletion, and concurrent-session tests pass.                                                                              |
| Browser    | Headed two-tab checks cover independent Account Caches, offline Progress and Problem Note edits, temporary auth loss, explicit sign-out hiding, account switching, reconnect/bootstrap repair, legacy import, refresh persistence, and confirmed deletion. |
| Production | Confirm the active Worker version, representative public routes, Clerk sign-in and account switching, authenticated sync, legacy endpoint contract, deletion status, and R2/cache health.                                                                  |

Passing unit tests or a successful build alone does not prove the local-first contract. A permanently offline browser cannot receive remote account deletion until it reconnects.
